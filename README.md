# Cross-model Activation Oracles on a concealing subject

Does an Activation Oracle whose backbone differs from the subject it reads escape the concept-specific anti-reading described in *When Activation Oracles Learn Not to Read* (Bersia and Gaintseva, arXiv 2607.23379)? Ten full-recipe oracles (five backbones, Qwen3-8B, Qwen3-14B, Qwen3-4B, Llama-3.1-8B and Mistral-7B, on each of two subjects) were trained on the activations of two Qwen3-8B Taboo subjects that hide a word, and evaluated on four prompt regimes with Karvonen's released oracle as reference.

Status: draft results, under review. Every number in the documents traces to `results/RESULTS.md`.

## What is here

| path | contents |
| --- | --- |
| `code/crossmodel_patch.py` | patches Karvonen's `activation_oracles` so the oracle and the subject are different models (separate frozen subject with the organism LoRA active during capture, separate tokenizers, zero-padding or truncation of activations, per-model revisions) |
| `code/apply_*.py` | the individual patch steps (injection recipe, padding, truncation, subject LoRA, hook-layer fix, resume from checkpoint) |
| `code/pod_setup.sh` | one-shot pod preparation: clone, patch, dependencies |
| `code/collect_readouts_xm.py` | cache-once evaluation: captures the subject's activations once, then reads them with any number of oracles, rebuilding the verbalizer prompt in each oracle's tokenizer |
| `code/checker_clock.py`, `code/checker_leaf.py` | frozen per-word disclosure checkers |
| `code/prompts/` | the THINK, OFFTOPIC and leaf-resolution prompt sets written for this project (the hint and denial sets are Karvonen's `datasets/taboo/`) |
| `code/semantic_judge_manual.py`, `results/semantic_judge_manual.md` | hand-graded semantic tiers (EXACT / NEAR / DOMAIN / OTHER) for every unique readout |
| `code/traj_analysis.py`, `results/trajectory_table.md` | checkpoint-trajectory analysis |
| `code/make_exec_figures.py` | the three summary figures |
| `results/readouts_xm_*.json` | every raw readout: per context, per oracle, per probe |
| `results/train_*.log`, `results/eval_*.log` | training and evaluation logs |
| `code/SMOKE-RESULTS.md` | incident log of the failed launches and their fixes |
| `experiments/tokenizer_kinship.py` | token-overlap measurements between the backbones |

Not included (kept locally, 90 GB): the trained adapters and intermediate checkpoints, the pod backups, the June 2026 capstone bundle with the clock organism adapter. The leaf subject and the paper's oracles are public at `Atmyre/ao-anti-reading` on Hugging Face.

## Reproducing a run

On a fresh RunPod pod (image `runpod/pytorch:1.0.2-cu1281-torch280-ubuntu2404`), copy `code/pod_scripts.tar` to `/workspace`, extract it and run `bash pod_setup.sh --no-smoke`. Training uses Karvonen's `sft.py` with the environment variables documented in `code/pod_setup.sh` (subject model, subject LoRA, oracle model, injection recipe). Evaluation is one call to `collect_readouts_xm.py` per regime; the exact invocations used are in `results/RESULTS.md` and the eval logs.

## Conventions in the documents

Every oracle reads the subject's activations over the prompt tokens alone; the subject generates no response and the secret word appears in no prompt. C1 is Karvonen's released Qwen3-8B oracle, trained on the clean base model's activations. All other oracles were trained from scratch on the subject's activations. Rates are per-context: the share of 100 prompts in which the oracle named the word at least once across its readouts, greedy decoding.
